# 阶段 7：上线与运营基础

准备完成时间：2026-08-11

## 目标

把 OpenVibe 从可构建的网站变成可重复发布、可监控、可回滚的服务，同时维持“自动发现不等于自动发布”的内容安全边界。

## 已落地

- CI 验证共享 Schema、数据、应用构建和生产 Compose 定义。
- 生产发布改为人工触发，并绑定 GitHub `production` Environment。
- 发布包只包含 Git 已跟踪文件，不携带本机环境文件或历史目录。
- 每个 Git SHA 建立独立服务器版本目录和 Docker 镜像。
- 容器健康失败自动恢复上一版本；公网检查失败同样触发回滚。
- 首页、健康接口、新手入口、发现页、作品页、更新日志和 RSS 共用冒烟检查。
- 公网每小时检查两次；监控只告警，不在无人审核时修改生产环境。
- 每周发现和项目更新任务保持 `contents: read`，只上传待审 artifact。
- 提供最小 Nginx 反向代理配置和服务器目录初始化脚本。

## 安全边界

- SSH 严格校验服务器主机公钥，不接受临时跳过验证。
- GitHub Secrets 只在单次发布 runner 中写入权限为 0600 的临时密钥文件，步骤结束即删除。
- 仓库不保存服务器密码、个人访问令牌、COS 密钥或数据库凭据。
- 生产发布需要人工触发；高风险内容更新仍需要独立显式审核。

## 当前数据策略

应用仍是无服务端用户数据的架构。项目内容由 Git 恢复，发布目录按版本保留；用户作品记录保存在浏览器并支持导出。数据库和 COS 生命周期属于账号与云端作品阶段，不能提前用生产凭据搭空壳。

## 剩余发布动作

代码侧发布基础已经完成。真正公网切换还需要：

1. 创建并连接 GitHub 仓库。
2. 在服务器安装新的专用部署公钥并完成一次性目录、Nginx、HTTPS 准备。
3. 在 GitHub `production` Environment 配置新生成的部署 Secrets。
4. 手动运行首次生产发布，并从公网完成验证。

这些动作涉及外部系统和生产写入，只能在新的安全访问通道可用后执行。
