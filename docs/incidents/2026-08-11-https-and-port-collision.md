# 2026-08-11：HTTPS 错证书与端口冲突

## 现象

- `http://vibe.yongle.school` 可以响应。
- `https://vibe.yongle.school` 因证书不包含该域名而被浏览器拒绝。
- 计划中的 OpenVibe 本机端口 `3100` 返回 404。

## 根因链

DNS 正确指向生产服务器，但 Nginx 中尚无 `vibe.yongle.school` 独立站点，因此 TLS 请求落入同机其他站点的默认证书；同时 `127.0.0.1:3100` 已被另一项 Node 服务占用，如果直接按原部署方案发布，会产生端口冲突或误判健康状态。

## 修复

- OpenVibe 生产端口统一改为 `127.0.0.1:3210`。
- Compose、部署检查、回滚检查、Nginx upstream 和运维文档同步修改。
- 为 `vibe.yongle.school` 创建独立 Nginx server block，并由 Certbot 申请匹配该域名的证书。
- 发布后同时验证本机健康接口与公网 HTTPS 七个关键入口。
- 首次镜像构建的依赖安装耗时约 11 分钟，期间 SSH 连接因无输出被中间网络回收；部署与回滚连接均增加 30 秒保活，避免长构建被误取消。

## 防复发

- 共享服务器部署前必须先取证端口占用，不能根据项目默认端口猜测。
- 修改健康端口时，Compose、部署、回滚、反向代理和公网监控必须同批修改。
- 只有 `000` 或 `5xx` 判为服务不可用，避免重定向或正常 4xx 触发错误重启。
- 远程构建必须启用 SSH keepalive；不能把“构建步骤长时间无日志”等同于进程已经失效。
