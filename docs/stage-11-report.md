# 阶段 11：真实试教验证冲刺

本地完成时间：2026-08-12

## 目标

冻结无证据的功能扩张，用两场标准化小规模试教验证 OpenVibe 的 K12 案例是否真正支持作者身份。同时偿还不改变产品边界的最小运维债务。

## 已完成的软件准备

- 新增 `/pilot/guide`，提供小学高段与初中两套可打印的 90 分钟执行协议。
- 两套协议统一现场节奏、作者证据四问、阶段成功线、隐私边界和暂停条件。
- `/pilot` 增加执行单入口，试教后仍使用本机匿名汇总，不接生产数据库。
- 公开更新历史补齐阶段 8、9、10，RSS 自动包含相同的已审核发布事件。
- 新增独立的重复采样延迟监控；单次慢只提醒，5 次中至少 3 次超过 8 秒才失败。
- 延迟监控只进入定时监控工作流，不进入部署冒烟检查，因此不会因变慢自动回滚。
- GitHub 官方 Actions 从 v4 升级至 v7，消除旧 Node 运行时弃用债务。

## 仍需真实世界完成

- 小学高段 4–8 人试教 1 场。
- 初中 4–8 人试教 1 场。
- 每场结束导出匿名 JSON，由项目负责人线下保管和比较。
- 两场完成后决定每条路线下一轮只修改一件事。

未执行试教前，不能宣称案例有效，也不应扩建账号、数据库、排行榜或更多 K12 案例。

## 验收口径

- 至少 70% 在 15 分钟内看到自己的可见变化。
- 至少 60% 完成可演示版本。
- 至少 50% 能清楚解释一个作者决定。
- 隐私合规率 100%，并记录成人介入分布。

## 运维边界

可用性冒烟仍以无法连接或 5xx 为失败条件，并可在部署中触发回滚。延迟监控用于发现 TLS 或网络抖动，只报告趋势，不修改服务器。自动发现和更新扫描仍只生成待审 artifact，无法自行发布。

## 下一阶段门槛

阶段 12 不以日期启动，而以证据启动：两场协议试教完成、匿名数据已复盘、至少形成两条具体路线修订决定。若没有这些证据，下一步应继续试教，不继续增加功能。
