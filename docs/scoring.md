# 学习价值评分

评分用于候选排序，不构成发布批准。

| 维度 | 上限 | 问题 |
|---|---:|---|
| 可复刻性 | 25 | 新手能否在合理时间内运行并做出变体？ |
| 清晰度 | 20 | README、目录、命名和边界是否清楚？ |
| 新手价值 | 20 | 是否能学到可迁移的方法而非一次性技巧？ |
| 产品完整度 | 15 | 是否呈现从需求到交付的完整产品结构？ |
| vibe coding 相关性 | 10 | 是否适合作为 AI 协作开发案例？ |
| 维护状态 | 5 | 项目是否仍可运行、依赖是否明显失效？ |
| 新颖性 | 5 | 是否提供不同于常见模板的思路？ |

## 准入硬门槛

- 公开仓库。
- 具有可识别许可证；无法识别时进入人工复核，不可直接发布。
- README 能说明用途和基本运行方式。
- 不是镜像、占位营销页或只有零散片段。
- 未归档、未禁用。
- 不需要执行仓库代码才能完成内容分析。

## 评分纪律

- 每个维度必须有文字依据。
- 总分必须等于七个维度之和，Schema 会强制校验。
- Star 只作为背景信息，不进入学习价值公式。
- 缺少证据时降低置信度或标记未知，不做确定性断言。
- 同一评分规则先在 5 个纵向样板上校准，再扩展到 30 个项目。
