# 架构决策记录

## ADR-001：静态优先

**决定**：MVP 使用版本化 JSON 内容构建静态页面，不引入生产数据库。

**原因**：30～200 个项目范围内，文件更易审核、回滚、测试与多 Agent 协作；线上页面不依赖 GitHub 实时可用性。

**复审条件**：需要用户收藏、投稿工作流或内容规模显著超过文件索引承载范围时。

## ADR-002：事实、判断、发布三层分离

**决定**：使用 `RepositorySnapshot`、`EditorialProfile`、`PublicationRecord` 三个独立对象，通过 `repositoryId` 关联。

**原因**：GitHub 更新不能覆盖编辑判断，编辑更新也不能伪造仓库事实；发布状态必须独立控制。

## ADR-003：稳定身份

**决定**：以 GitHub 数字 `repositoryId` 为实体主键，`owner/name` 只是可变化快照。

**原因**：仓库可以改名或转移所有者，但数字 ID 保持实体连续性。

## ADR-004：审核门

**决定**：自动流程最高只能把项目推进到 `review`；`published` 必须同时满足编辑内容已批准、发布时间存在、数据完整。

**原因**：模型评分用于缩小候选范围，不应替代发布责任。

## ADR-005：GitHub API 使用边界

**决定**：抓取端使用版本化 REST API、条件请求和串行队列；处理 `ETag`、`304`、`403`、`429`、重定向及指数退避。

**原因**：GitHub 官方建议避免轮询和并发请求，优先认证、缓存及条件请求。当前契约基于 `X-GitHub-Api-Version: 2026-03-10`，实现阶段若官方版本变化必须先更新 fixture 与契约测试。

参考：

- <https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api>
- <https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api>

## ADR-006：摘要而非复制

**决定**：仅保存有限长度 README 摘要、证据路径与来源链接，不保存整篇 README 用于公开展示。

**原因**：降低内容过期、版权和数据膨胀风险，同时保留判断依据。

## ADR-007：更新候选与公开快照隔离

**决定**：定时扫描把新快照写入临时待审目录，不覆盖 `data/snapshots` 或 `data/projects`。只有显式审核命令可以同步公开数据。

**原因**：GitHub 事实会随时变化，但许可证、维护状态和 README 变化可能使旧编辑判断失效。隔离后能在自动检测与发布责任之间保留审核门。

## ADR-008：RSS 先于邮件订阅

**决定**：静态阶段先提供 RSS 更新源。邮件订阅在服务器数据库、退订和发送身份完成配置后再开放。

**原因**：RSS 无需收集个人数据，可与静态更新历史使用同一数据源；邮件订阅则必须先解决同意、退订、安全与发送可达性。

## ADR-009：年龄是任务推荐，不是学习者身份

**决定**：K12 年龄段只写入任务的学习设计，不写入本机作品记录，也不要求学习者填写生日、学校或班级。任务可以同时推荐给相邻年龄段，但必须指定一个主要设计年龄段。

**原因**：年龄可以帮助控制文字量、成人支持和作品复杂度，却不能替代对兴趣与能力的判断。当前产品没有建立处理未成年人身份数据所需的监护同意、删除和访问控制，因此不得以筛选功能为由提前采集。

## ADR-010：学习路线是作品周期，不是任务清单

**决定**：每条 K12 路线用 5 个案例提供兴趣选择，但学习者只选一个案例完成四周。路线本身不写入浏览器进度，不产生连续打卡、积分、徽章或排行榜。

**原因**：产品希望支持作者身份和真实作品，而不是用完成数量代替学习质量。把路线建成任务清单会鼓励快速勾选，也会过早引入未成年人行为画像。单个作品已有版本化进度 Schema，四周路线只负责提供意图、制作、反馈和展示的教学结构。

**复审条件**：真实试教证明跨设备连续性确有必要，并且监护同意、访问控制、导出删除和数据最小化已经设计和验证。

## ADR-011：试教反馈先本机汇总，不直接写生产数据库

**决定**：阶段 10 的试教反馈只记录一次活动的匿名汇总，使用版本化 Schema 保存到当前浏览器，并由引导者主动导出。站点不提供自动上传、儿童记录、机构账号或跨设备同步。

**原因**：路线尚在真实验证期，先明确哪些数据确有改进价值，再承担服务端数据治理成本。即使不要求姓名，路线年龄段、自由文本和活动日期组合也可能产生再识别风险；本机优先能把暴露面降到最低，同时保留离线复盘能力。

**复审条件**：至少完成 2–4 次真实试教，证明集中汇总有持续价值，并先完成数据保留期限、访问权限、监护同意、导出删除、事件审计和自由文本脱敏设计。

## ADR-012：真实试教证据先于功能扩张

**决定**：阶段 11 固定两套 90 分钟小规模试教协议，先验证小学高段与初中各一场。协议统一观察快速可见、演示版本、成人介入和作者身份四维；在真实记录完成前，不增加账号、数据库、排行或更多案例。

**原因**：当前内容数量已经足够验证核心命题，继续扩张会掩盖案例是否真正可教、作品是否真正属于学习者。标准协议让不同场次结果可比较，同时避免把活动结果变成儿童评分。

**复审条件**：至少两场试教完成并形成明确路线修订决定。

## ADR-013：延迟告警与可用性回滚分离

**决定**：部署冒烟把无法连接、传输不完整或 5xx 视为故障，并对失败路由做一次有界复核；复核仍失败才回滚。重复延迟采样放在独立监控任务中，只告警、不触发生产回滚。

**原因**：公网和 TLS 偶发抖动不等于应用版本故障，但拿到 HTTP 状态后响应体传输失败也不能算健康。有界复核兼顾瞬时抖动与持续故障；独立重复采样保留趋势证据，再由人工区分应用、共享服务器、网络或证书链问题。
